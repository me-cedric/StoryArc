# Project Constitution

Version: 0.1.0
Last amended: YYYY-MM-DD

## Purpose

This constitution records non-negotiable principles for this project. Agents and
developers must use it when writing specs, plans, tasks, implementation, tests,
and documentation.

## Principles

### 1. User Intent First

Specifications describe what users need and why before technical choices are
made.

### 2. Smallest Safe Change

Prefer the smallest implementation that satisfies the approved spec. Avoid
speculative abstractions and future-only scaffolding.

### 3. Testable Requirements

Every requirement must have acceptance criteria that can be verified by tests,
manual checks, or explicit review.

### 4. Documentation Stays Current

When behavior, setup, contracts, or architecture change, update the relevant
specs and documentation in the same task.

### 5. Validation Is Part Of Done

Completion requires the scoped lint, typecheck, tests, and any project-specific
checks named in the plan.

## Governance

- Amend this file by changing the version and adding an entry below.
- Treat stricter host-project rules as higher priority than generic baseline
  guidance.
- Review this constitution when project direction, stack, or quality standards
  change.
